**Baza (produkcja):** `https://api.klovy.chat`  
**Baza (lokalnie):** `http://127.0.0.1:8080`  
**WebSocket:** `wss://api.klovy.chat/ws` (lokalnie Vite proxy `/ws`)

To są te same ścieżki, które woła appka z `src/api/*.ts`. Po drugiej stronie siedzi `src/routes/*.rs`. Osobnego API dla botów nie ma i nie planujemy go doklejać „obok”. Nowy endpoint, którego nie ma w obu miejscach, po prostu nie istnieje — 404 albo martwy przycisk.

Body, kody i limity są na podstronach. Tu jest mapa, żeby nie szukać pathu w dwudziestu plikach Rusta. Aliasy w nawiasie działają, kanoniczne są te, których używa obecny frontend.

Sesja to ciasteczka HttpOnly, nie Bearer w `localStorage`. Fetch musi iść z `credentials: include`. JSON w obie strony. `/api/channel` i `/api/channels` (i analogicznie message/friend/contact) to aliasy na ten sam kontroler, bo historycznie klient wzywał raz pojedynczą, raz mnogą.

Każde żądanie z appki wygląda mniej więcej tak:

```http
X-Klovy-Client: KlovyChatApp/1.0
X-Klovy-User-Agent: …
Cookie: …access…; csrf_token=…
X-CSRF-Token: <ta sama wartość co cookie csrf_token>
```

CSRF na `POST` / `PUT` / `PATCH` / `DELETE`. Wyjątki: signup, login, login/2fa, refresh. GET/HEAD/OPTIONS bez tokena. Jak cookie i nagłówek się rozjadą, dostaniesz 403 z `Invalid or missing CSRF token`, nie 401.

## Bootstrap

```http
GET /api
GET /api/
GET /
```

Zwraca wersję, flagi, limity, URL-e WS i aplikacji:

```json
{
  "klovy": "semver",
  "ws": "wss://api.klovy.chat/ws",
  "app": "https://app.klovy.chat",
  "features": {
    "captcha": { "enabled": true, "service": "turnstile" },
    "email": false,
    "invite_only": false,
    "cdn": { "enabled": true, "url": "https://cdn.klovy.chat" },
    "livekit": { "enabled": true, "nodes": [] },
    "limits": {
      "global": {
        "message_reactions": 20,
        "message_replies": 1,
        "message_embeds": 1
      },
      "default": {
        "message_length": 2000,
        "message_attachments": 1
      }
    }
  }
}
```

## Katalog REST

Kanoniczne ścieżki, aliasy w nawiasie. Body na podstronach.

### Publiczne / sesja

| Metoda | Endpoint | Auth |
| --- | --- | --- |
| `GET` | `/api` | nie |
| `GET` | `/api/auth/registration-status` | nie |
| `POST` | `/api/auth/signup` (`/register`) | nie + Turnstile |
| `POST` | `/api/auth/login` (`/sign-in`, `/signin`) | nie + Turnstile |
| `POST` | `/api/auth/login/2fa` | token 2FA + Turnstile |
| `POST` | `/api/auth/refresh` | cookie refresh |
| `POST` | `/api/auth/logout` | sesja |
| `GET` | `/api/auth/userinfo` (`/me`, `/user`, `/api/auth`) | sesja |
| `POST` | `/api/auth/ws-crypto` | sesja |
