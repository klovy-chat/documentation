**Base (production):** `https://api.klovy.chat`  
**Base (local):** `http://127.0.0.1:8080`  
**WebSocket:** `wss://api.klovy.chat/ws` (locally via Vite proxy `/ws`)

These are the same paths the app calls from `src/api/*.ts`. On the other side sits `src/routes/*.rs`. There is no separate bot API, and we are not planning to bolt one on “alongside”. A new endpoint that does not exist in both places simply does not exist — 404 or a dead button.

Request bodies, status codes, and limits are on the subpages. This page is the map so you do not have to hunt for a path across twenty Rust files. Aliases in parentheses work; the canonical ones are those the current frontend uses.

The session lives in HttpOnly cookies, not a Bearer token in `localStorage`. Fetch must use `credentials: include`. JSON both ways. `/api/channel` and `/api/channels` (and similarly message/friend/contact) are aliases to the same controller, because historically the client called singular and plural forms interchangeably.

Every request from the app looks roughly like this:

```http
X-Klovy-Client: KlovyChatApp/1.0
X-Klovy-User-Agent: …
Cookie: …access…; csrf_token=…
X-CSRF-Token: <same value as csrf_token cookie>
```

CSRF on `POST` / `PUT` / `PATCH` / `DELETE`. Exceptions: signup, login, login/2fa, refresh. GET/HEAD/OPTIONS without a token. If the cookie and header do not match, you get 403 with `Invalid or missing CSRF token`, not 401.

## Bootstrap

```http
GET /api
GET /api/
GET /
```

Returns version, flags, limits, WS and app URLs:

```json
{
  "klovy": "semver",
  "ws": "wss://api.klovy.chat/ws",
  "app": "https://app.klovy.chat",
  "features": {
    "captcha": { "enabled": true, "service": "turnstile" },
    "email": false,
    "invite_only": false,
    "cdn": { "enabled": true, "url": "https://cdn.klovy.chat" },
    "livekit": { "enabled": true, "nodes": [] },

        "message_embeds": 1
      },
      "default": {
        "message_length": 2000,
        "message_attachments": 1

    }
  }
}
```

## REST catalog

Canonical paths; aliases in parentheses. Request bodies on the subpages.

### Public / session

| Method | Endpoint | Auth |
| --- | --- | --- |
| `GET` | `/api` | no |
| `GET` | `/api/auth/registration-status` | no |
| `POST` | `/api/auth/signup` (`/register`) | no + Turnstile |
| `POST` | `/api/auth/login` (`/sign-in`, `/signin`) | no + Turnstile |
| `POST` | `/api/auth/login/2fa` | 2FA token + Turnstile |
| `POST` | `/api/auth/refresh` | refresh cookie |
| `POST` | `/api/auth/logout` | session |
| `GET` | `/api/auth/userinfo` (`/me`, `/user`, `/api/auth`) | session |
| `POST` | `/api/auth/ws-crypto` | session |
