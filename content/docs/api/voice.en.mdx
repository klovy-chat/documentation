Prefix `/api/voice` (alias `/api/voices`). Session, CSRF on POST. Only the token goes through here — media flows to LiveKit, not through Actix. Ring and hangup are `call:*` / `channel-voice:*` frames. 1:1 order: invite frame, then token, then connect. On a channel, without `channel-voice:join` the mic will not come up, even if you already have the JWT.

The client rejects `url` outside `VITE_LIVEKIT_ALLOWED_HOSTS`. Backend signs with `LIVEKIT_API_KEY` / `SECRET`.

## POST `/api/voice/token`

Aliases: `POST /api/voice`, `/call/token`.

DM:

```json
{ "peerId": "userId" }
```

Channel:

```json
{ "channelId": "channelId" }
```

```json
{
  "token": "eyJ…",
  "url": "wss://….livekit.cloud",
  "room": "…"
}
```

The client rejects `url` outside `VITE_LIVEKIT_ALLOWED_HOSTS` (e.g. `*.livekit.cloud`). Backend signs the token with `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET`.

## GET `/api/voice/active`

```json
{
  "active": true,
  "peerId": "…",
  "mode": "audio"
}
```

`mode`: `audio` | `video`.

## Signaling (WS, not REST)

| `type` | Direction |
| --- | --- |
| `call:invite` | client → server |
| `call:incoming` | server → UI calendar |
| `call:accept` / `call:accepted` | accept |
| `call:reject` / `call:rejected` | reject |
| `call:cancel` / `call:cancelled` | cancel |
| `call:end` / `call:ended` | hang up |
| `call:timeout` | no answer |
| `call:unavailable` | busy / offline |
| `channel-voice:join` / `leave` / `state` | channel voice |
