Slugs: [routes](/docs/product/interface). Mutations: [auth](/docs/api/auth). CSRF on POST/PATCH/DELETE — if profile save returns 403 with `Invalid or missing CSRF token`, cookie and header drifted, not "bad bio".

| In UI | Request |
| --- | --- |
| Display name, bio, color | `POST /api/auth/update-profile` `{ displayName, bio?, color? }` |
| Avatar / banner | `POST` multipart, remove with `DELETE` |
| Username | `POST /api/auth/change-username` `{ username, password, code? }` |
| Password | `POST /api/auth/change-password` `{ currentPassword, newPassword, code? }` |
| 2FA | `/api/auth/2fa/setup` · `enable` · `disable` |
| Disable / delete | `/api/auth/account/*` + password (and TOTP if on) |

Avatar ~6 MiB, banner ~7 MiB. Password, username, upload, and 2FA have separate limits — 429 on nickname change doesn't mean login is broken too.

`GET /api/auth/sessions` — devices. Revoking current closes WS (`session:revoked`). `revoke-others` keeps this tab, logs out the rest. "Log out other devices" should call that, not a loop of `DELETE` over the list.

In UI: Available → `online`, Unavailable looks offline (`away`), Be right back → `brb`, Do not disturb → `dnd`. Idle uses the same POST as manual change. Don't send status again over WS.

Language is on the account (`PATCH /api/auth/language`). Theme is client-only. Voice (devices, PTT, share quality) too — server doesn't store chosen mic. Warnings: `GET /api/auth/warnings` + `acknowledge`. Announcements similarly, dismiss separately.
