HTTP paths and WS frames live in [API](/docs/api). This section covers what people get wrong when they come from Discord or Slack and try to map things 1:1.

There is no server (guild) above channels. A channel is just a group: name, avatar, member list, one `admin`. That admin is the creator, full stop. No roles, no "moderator with half the permissions", no bot sitting on the channel. You can't open a DM to a random username — friends first (or `autoAccepted` if both sides crossed requests).

| Term | Here |
| --- | --- |
| Account | `username` 3–32, `[a-z0-9_]`. You log in with `@name`, not email. We don't collect email at signup at all. |
| Channel | One group, one `admin`. |
| Friend | No DM without acceptance. |
| Chat | Either `contactId` or `channelId`. Don't mix both in one body — the backend won't guess. |
| Owner | Channel creator. Don't look for another permission matrix in the code — there isn't one. |

After login the app holds cookies and CSRF. Production adds Turnstile; with 2FA you also get TOTP. If the account is stuck on the whitelist, the only legal screen is `/pending`. WebSocket **must not** open there — the handshake will fail anyway and you'll pollute the logs. Once the session is "full": `GET /api` (limits, flags), `POST /api/auth/ws-crypto` (frame key), upgrade `/ws`, then REST for channel/contact lists and history, live traffic goes over frames.

Don't add these because "everyone has them": E2EE (E2E keys left the repo — don't restore them in a PR without talking first), bots, webhooks, OAuth apps, public channel directory, native Android/iOS, Spotify wired to profile. In chat, Spotify stays as an embed from `link-preview`, nothing more.

Voice is not a separate "room". You fetch the LiveKit token over HTTP; ring and join go over frames. Media doesn't hit Actix. Files from chat don't go straight to CDN either — quarantine and ClamAV first.
