Trasy siedzą w `pages/`. Guard auth i whitelist jest w kontekście, nie w jakimś `loaderze` React Routera — jak nowy ekran ma być tylko dla zalogowanych, dopinasz ten sam kontekst, nie piszesz drugiej bramki. Stringi UI: `pl.json` i `en.json`, zawsze oba. Slugi ustawień zostają po angielsku (`/settings/account`), etykiety biorą się z i18n.

| Path | Co tam jest |
| --- | --- |
| `/login`, `/signup` | sesja; na prodzie Turnstile |
| `/setup` | profil po pierwszym logowaniu |
| `/pending` | whitelist, bez WS |
| `/` | lista i konwersacja |
| `/invite/:id` | podgląd + `POST /api/invite/{id}/accept` |
| `/settings/*` | panel |

Na szerokim ekranie masz sidebar (kanały, DM, szukajka **nazw** czatów, nie treści wiadomości), środek z historią i pinem, composer na dole. Pod spodem emoji, GIF, naklejki, plik i call. Na wąskim lista i czat się przełączają — to ten sam stan, tylko inny układ, nie dwa widoki z osobnymi fetchami. Klik w nagłówek otwiera szczegóły kanału albo profil kontaktu. Nieprzeczytane widać na liście; na desktopie jeszcze badge, który czyta `(N)` z tytułu.

`/pending` nie jest „ładnym ekranem oczekiwania”. Konto ma ciasteczka, ale kanały, wiadomości, znajomi i handshake WS i tak padną. Nie otwieraj socketa „na wszelki wypadek” — dostaniesz reconnect-loop i śmieć w logach.

Nowa zakładka w ustawieniach: wpis w `settings/routes.ts`. Slug po angielsku, label z JSON-a.

| W UI | Path |
| --- | --- |
| Moje konto | `/settings/account` |
| Profil | `/settings/profile` |
| Urządzenia | `/settings/sessions` |
| Status | `/settings/status` |
| Głos | `/settings/voice` |
| Język | `/settings/language` |
| Ostrzeżenia | `/settings/warnings` |

Język (`pl` / `en`) idzie `PATCH /api/auth/language` i ląduje na koncie, więc nowa przeglądarka dostanie ten sam. Motyw jasny/ciemny zostaje w kliencie — serwer o nim nie wie.

Katalogi i konwencje: [Frontend](/docs/developers/frontend).
