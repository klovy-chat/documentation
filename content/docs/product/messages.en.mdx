title: Messages
description: Send goes over WebSocket; HTTP is history and files.

HTTP details: [messages API](/docs/api/messages). Frames: [WebSocket](/docs/api/websocket). DM and channel differ by recipient (`recipient` vs `channelId`); the rest of the payload is the same. Don't mix both in one body — the backend won't guess.

Max **2000** characters (same in `GET /api`). Types: `TEXT`, `FILE`, `IMAGE`, `VIDEO`, `AUDIO`, `STICKER`, `CALL`. On send include `clientNonce` (UUID). Without it the server won't dedupe retries and on a flaky WS you get duplicates. Quote: `quotedMessage`. Max 20 reactions per message. Bold, italic, strikethrough, and code are assembled client-side — the server holds a string, not a markdown AST.

You **don't** send new messages over REST. In the app that's `sendMessage` / `send-channel-message`. `PUT` and `DELETE /api/messages/{id}` exist, but edit and delete from UI go over WS. Keep HTTP for history, pins, search, and upload.

DM history: `POST /api/messages/get-messages` `{ id, before?, limit? }` → `{ messages, hasMore }`. Channel: `GET /api/channel/get-channel-messages/{id}?before=&limit=`. Content search: `POST /api/messages/search` with `contactId` **or** `channelId`, min. 2 characters. Sidebar search only looks at chat names — if someone types a message fragment there, nothing shows up and that's not a bug. Pins: `POST /api/messages/pinned` and `POST`/`DELETE …/{id}/pin`.

Upload: multipart `file`, `contentType`, `contextType` (`dm`|`channel`), `contextId`, ~10 MB. `scanStatus`: `pending` / `clean` / `blocked`. Blocked files don't reach CDN; UI should show scan failed, not spin forever. GIF and sticker are URLs from `/api/gifs` / stickers, then the same WS frame with `fileUrl`. Link preview: `POST /api/messages/link-preview` — YouTube, Spotify player. We don't wire Spotify to profile, only that embed.

On a channel `chatLocked` hides the composer for non-admins. `rateLimitPerUser` is seconds between sends (`0` disables). State also arrives via `channel-chat-locked-updated` / `channel-slowmode-updated` frames, so you don't need to refetch details after every PATCH. Mentions `@user` / `@everyone` / `@here` → `message-mention`. Read state: `mark-conversation-read` / `mark-channel-read`. Desktop badge reads `(N)` from title — if you count unread in state but don't touch `document.title`, the Dock stays on the old number.
