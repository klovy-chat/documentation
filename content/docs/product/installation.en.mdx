There is one web client. No "desktop version with different buttons" — Tauri loads [app.klovy.chat](https://app.klovy.chat) or the origin from config and adds a window, badge, and updater. If something looks wrong in the app, check the frontend first, not `src-tauri`. Build and signing: [Desktop](/docs/developers/desktop).

In production the frontend runs on Cloudflare Workers. Locally Vite on `:5173` proxies `/api`, `/whitelist`, and `/ws` to the backend, so in DEV you rarely hit the browser straight at `:8080`. Chrome, Edge, Firefox, and Safari from this decade are fine. On mobile the page loads; layout is trimmed for a narrow screen. We don't ship separate Android/iOS apps and don't plan to bolt them onto the `application` repo.

| OS | Package | Note |
| --- | --- | --- |
| Windows | `.msi` / NSIS, Store | WebView2; Store updates itself |
| Linux | AppImage, `.deb`, `.rpm` | WebKitGTK 4.1 when building from source |
| macOS | `.dmg` universal, App Store | badge on Dock |

Ready builds: [Releases](https://github.com/klovy-chat/application/releases) or the download page. CI signs with `TAURI_SIGNING_PRIVATE_KEY`. The GitHub updater only works on a **public** release — a private draft returns 404 and logs look like the package is bad.

The badge reads the count from the window title, e.g. `(2) Klovy Chat`. The frontend sets `document.title`; the shell doesn't count on its own. Don't test this in `tauri dev` — only on an installed build. Same for the updater: `latest.json` from Releases; the Store variant leaves those endpoints empty. There's also Discord Rich Presence — a Tauri plugin, not a separate service.

Windows without WebView2 = blank window. Linux without WebKit = black screen. If you change the title format to something like `Klovy Chat — 2`, the badge drifts from the shell and you'll hunt a bug in Rust when the problem is one string on the frontend.
