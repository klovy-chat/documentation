Repo: [klovy-chat/backend](https://github.com/klovy-chat/backend). The binary is named `klovy-chat-server`. Public port (default 8080) is Axum; Actix sits beside it on internal HTTP and serves `/api/*` plus `/ws` upgrade.

Rest of the stack: MongoDB Atlas, Cloudflare R2, ClamAV, LiveKit tokens, Argon2 for passwords, JWT in cookies, AES-GCM on some fields and WS frames, TOTP for 2FA.

```
src/
├── main.rs           start, Mongo indexes, bind
├── routes/           /api/*
├── controllers/      logic
├── model/            Mongo documents
├── ws/               handshake, encrypt, handlers
├── middlewares/      auth, CSRF, captcha, origin, whitelist
└── utils/            storage, scan, crypto
```

For a new endpoint, register it first in `routes/*.rs` — there you decide public vs `verify_token`, Turnstile, rate limiter. Then the function in `controllers/`. Do it the other way around and the route does not exist and you spend an hour hunting a typo in the handler name.

| Group | Examples |
| --- | --- |
| Server | `PORT`, `INTERNAL_HTTP_PORT`, `TRUST_PROXY`, `NODE_ENV` |
| Database | `MONGODB_URI`, `DB_NAME` |
| Auth | `JWT_KEY`, `FIELD_ENCRYPTION_KEY`, `TOKEN_HASH_KEY` |
| CORS | `ORIGIN`, `FRONTEND_URL` |
| Captcha | `TURNSTILE_SECRET_KEY` |
| Storage | `R2_*`, `CDN_PUBLIC_BASE_URL`, `R2_QUARANTINE_BUCKET` |
| Scan | `CLAMAV_HOST` |
| Voice | `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` |

In production Origin and Frontend must be HTTPS. Quarantine bucket must be **different** from the public CDN. ClamAV must be on in prod; dummy host in DEV is only so the process starts.

Actix middleware order, roughly: compression, security headers, limits, client guard, origin, **CSRF**, JSON sanitization, proxy, scope `/api/…`. Login, signup, login/2fa, and refresh skip CSRF — other mutations want cookie `csrf_token` and the same string in `x-csrf-token`. GET/HEAD/OPTIONS without CSRF.

Channels, messages, and friends also go through the whitelist. A "pending" account has valid cookies, but those scopes and WS handshake still fail. UI should keep that user on `/pending`, not "try chat until it works".

The repo has `encrypt-old-messages` (legacy records), `Caddyfile.example` (`:8081` → `:8080`), Compose with profile `scan`, and `deploy.yml` on `main`. Deploy workflow will not run on a fork — that is intentional in the yaml. We do not commit prod env; template is in `.env.example`.
